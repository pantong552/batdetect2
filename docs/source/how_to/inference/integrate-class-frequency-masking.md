# Integrate class-frequency masking in another web app

Use this guide to apply the frequency-based class mask generated by BatDetect2
to call identification in a separate web application.

This is an inference-time decoding rule. It does not change model weights or
training targets, and it does not require retraining.

## Mask configuration

The Training Studio's **Generate Class Mask** action writes
`outputs/class_mask_outputs.yaml` and fills the Quick inference frequency
ranges field. The generated file has the same transform structure:

```yaml
transform:
  detection_transforms:
    - name: mask_classes_by_frequency
      class_ranges:
        nycpla:
          low_freq:
            min: 17460
            max: 27997
          high_freq:
            min: 21393
            max: 54759
  clip_transforms: []
```

The numbers above are an example from `Test_data`; use the actual generated
file for your dataset. Frequency values are in Hz. A class key such as `nycpla`
must match the model's target class name, not necessarily the full species
label in the annotation file.

Each configured class has an inclusive allowed range for both predicted call
boundaries:

```text
low_freq.min <= predicted_low_freq <= low_freq.max
high_freq.min <= predicted_high_freq <= high_freq.max
```

If either boundary is outside its range, that class is ineligible for the
detection. In the current BatDetect2 transform, classes omitted from
`class_ranges` are left unchanged and remain eligible. For a fully constrained
identification result, make sure every model class has a range in the file.

## Where to apply the mask

Apply the rule after decoding each model candidate's class score vector and
time-frequency geometry, but before choosing or presenting its identified
class. Do not filter away the entire detection just because one class is
ineligible: another class may still be a valid match.

For each candidate detection:

1. Keep its complete class score vector in the model's target-class order.
2. Decode the predicted geometry and read `low_freq` and `high_freq` in Hz.
3. For each class with a configured range, set its score to zero if either
   boundary is outside its inclusive range.
4. Choose the highest-scoring class whose score remains greater than zero.
5. If no class remains, report the event as `Unknown` / unclassified. Do not
   use `argmax` on an all-zero vector: it would incorrectly choose index zero.

Example TypeScript-style decoding:

```ts
type FrequencyRange = { min: number; max: number };
type ClassFrequencyRange = {
  low_freq: FrequencyRange;
  high_freq: FrequencyRange;
};

function applyClassFrequencyMask(
  classNames: string[],
  scores: number[],
  lowFreqHz: number,
  highFreqHz: number,
  classRanges: Record<string, ClassFrequencyRange>,
) {
  if (scores.length !== classNames.length) {
    throw new Error("Class score count does not match model class names.");
  }

  const maskedScores = scores.map((score, index) => {
    const range = classRanges[classNames[index]];
    if (!range) return score;

    const lowFits =
      range.low_freq.min <= lowFreqHz &&
      lowFreqHz <= range.low_freq.max;
    const highFits =
      range.high_freq.min <= highFreqHz &&
      highFreqHz <= range.high_freq.max;
    return lowFits && highFits ? score : 0;
  });

  let bestIndex = -1;
  for (let index = 0; index < maskedScores.length; index += 1) {
    if (
      maskedScores[index] > 0 &&
      (bestIndex < 0 || maskedScores[index] > maskedScores[bestIndex])
    ) {
      bestIndex = index;
    }
  }

  return {
    classScores: maskedScores,
    className: bestIndex < 0 ? "Unknown" : classNames[bestIndex],
    classScore: bestIndex < 0 ? 0 : maskedScores[bestIndex],
  };
}
```

The mask only zeros disallowed scores; it does not renormalize the remaining
scores. Ranking by the largest remaining score gives the highest-scoring
eligible class. If the UI labels the score as a probability, retain that
distinction: after masking, the scores are not renormalized probabilities.

## Load and validate the generated file

Load `outputs/class_mask_outputs.yaml` on the web-app server, or pass its
`transform.detection_transforms` section through the existing model
configuration path. Parse YAML with a YAML library and validate the shape
before inference. Do not hard-code the example ranges above.

At startup or when the user changes the config, validate that:

- a transform named `mask_classes_by_frequency` is present;
- each configured class name exists in the loaded model's class list;
- each class has both `low_freq` and `high_freq` ranges;
- each range has numeric `min` and `max` values, `min <= max`, and uses Hz;
- the class score vector has the same ordering and length as the model's class
  name list.

Surface invalid configuration as an error instead of silently skipping the
mask. If dataset classes cannot be mapped to model target names, resolve that
mapping in the targets configuration before generating or applying the mask.

## Preserve the mask through output formatting

Use the masked class score vector to generate all class-dependent output:

- the top class name and its class score;
- any ranked class list or species tags;
- the recording-level or clip-level class summary, if the web app computes
  one.

Otherwise, a detection may display a masked top class in one view but still
contribute its unmasked score to a summary elsewhere. Keep the detection score
separate: class masking changes only the class scores and must not change the
detection score, geometry, or whether the call was detected.

When no class is eligible, preserve the detection geometry and detection score,
but emit no species class (or display `Unknown`). Validate the behavior on
reviewed local recordings, especially calls near the configured boundaries.
